ПОДСКАЗКИ ПО ПРОЕКТУ: ДИАГНОСТИКА ОБУЧЕНИЯ НЕЙРОСЕТИ

1. ЧТО ТАКОЕ ДАТАСЕТ HIGGS

HIGGS — набор данных для бинарной классификации в физике частиц.
Он содержит 11 000 000 примеров. Каждый пример описан 28 числовыми
признаками и одной меткой класса: всего 29 столбцов.

Важно: эти данные получены методом Монте-Карло — компьютерной
симуляцией физических процессов. Это не сырые измерения реального
эксперимента. Симуляция позволяет получить примеры с известным ответом.

2. ЧТО ОЗНАЧАЕТ ОДНА СТРОКА — ОДНО СОБЫТИЕ

Событие — отдельный смоделированный случай столкновения частиц
и его результат, представленный характеристиками конечных частиц.
Строка содержит числовое описание события, а не фотографию столкновения.

Метка показывает, к какому из двух процессов относится событие:
  y = 1 — сигнальный процесс, в котором образуется бозон Хиггса;
  y = 0 — фоновый процесс, в котором он не образуется.

Задача модели — по характеристикам события отличить сигнал от фона.
Это учебная задача распознавания закономерностей в симулированных данных;
обучение на этом датасете само по себе не является открытием частицы.

3. ЧТО НАХОДИТСЯ В 29 СТОЛБЦАХ

Ниже используется нумерация Python, начиная с нуля:
  Столбец 0:       метка класса y — правильный ответ, 0 или 1.
  Столбцы 1–21:    21 исходный кинематический признак.
  Столбцы 22–28:   7 производных признаков, вычисленных из исходных.

Кинематические признаки описывают движение и расположение частиц.
Например, в HIGGS есть поперечный импульс лептона, его направления,
характеристики четырёх струй частиц и недостающего поперечного импульса.

Пояснения для понимания (упрощённо):
  Лептон — тип элементарной частицы; электрон и мюон — примеры лептонов.
  Струя (jet) — группа частиц, летящих примерно в одном направлении.
  Поперечный импульс — составляющая импульса поперёк оси пучков.
  Недостающий поперечный импульс — дисбаланс наблюдаемых поперечных
  импульсов; он может указывать на невидимые детектору частицы.

Производные признаки — физические величины, рассчитанные из исходных
характеристик. В этом датасете они связаны с массами комбинаций частиц.
Это не семь дополнительных событий и не семь целевых ответов.

Точные имена, порядок признаков и физическое описание нужно сверять
с официальной карточкой и статьёй; названия не следует угадывать.

4. ЧТО ТАКОЕ X И y

X — входные признаки: то, что модель получает для предсказания.
y — целевая метка: правильный ответ для обучения и проверки.

Для N примеров:
  Вся таблица: (N, 29)
  X:           (N, 28)
  y:           (N,)

Пример для 1000 строк:
  1000 событий, у каждого по 28 входных признаков и одной метке.

Логика модели:
  28 признаков события → нейросеть → оценка вероятности класса 1.

Если модель выдаёт 0.8, это её оценка вероятности сигнального класса,
а не «80% бозона Хиггса внутри события». Насколько вероятности модели
соответствуют реальным частотам, требует отдельной проверки.

Столбец y нельзя включать в X: иначе модель получает правильный ответ
на вход. Это утечка целевой переменной, и такая оценка качества обманчива.

CSV — текстовая таблица: строки разделены переносами строк,
а значения в HIGGS разделены запятыми. В исходном файле нет строки

После распаковки в CSV смысл данных, число признаков и метки не меняются.

7. train_test_split — РАЗДЕЛЕНИЕ ДАННЫХ

Импорт:
from sklearn.model_selection import train_test_split

scikit-learn — библиотека машинного обучения; в коде её имя — sklearn.
model_selection — модуль с инструментами выбора и проверки моделей.
train_test_split — функция, которая разделяет данные на две части.
Строка импорта делает функцию доступной в нашем файле, но сама ещё
ничего не разделяет и не обучает.

Зачем разделять данные:
  train — примеры, на которых модель обучает свои веса;
  validation — примеры для выбора настроек и контроля обучения;
  test — отложенные примеры для финальной оценки выбранного решения.
Проверка только на обучающих примерах не показывает, насколько хорошо
модель работает на новых данных: она могла запомнить обучающие примеры.

Пример из нашего проекта:
X_train, X_rest, Y_train, Y_rest = train_test_split(
    X, Y, test_size=0.30, random_state=12, stratify=Y
)

X и Y передаются вместе: соответствие признаков и ответов сохраняется.
Порядок результатов: первая часть X, вторая часть X,
первая часть Y, вторая часть Y.

Параметры:
  test_size=0.30 — отложить 30% переданных строк во вторую часть.
  Имя параметра не обязывает считать эту часть финальным test:
  у нас сначала это X_rest и Y_rest.
  random_state=12 — фиксировать случайное разбиение для повторяемости
  при одинаковых входных данных. Число 12 не обладает особым свойством.
  stratify=Y — сохранить примерно одинаковые доли классов 0 и 1.
  Перемешивание включено по умолчанию.

Для 300 строк: 210 идут в train, 90 — в rest.
Второй вызов делит rest пополам:
X_validation, X_test, Y_validation, Y_test = train_test_split(
    X_rest, Y_rest, test_size=0.50, random_state=12, stratify=Y_rest
)
Получаются 45 validation и 45 test: по 15% исходных 300 строк.
Во втором вызове test_size относится именно к оставшимся 90 строкам.
На таких маленьких выборках качество будет сильно колебаться;
сейчас они нужны для отладки, а не для убедительной оценки модели.

8. StandardScaler — МАСШТАБИРОВАНИЕ ПРИЗНАКОВ

Импорт:
from sklearn.preprocessing import StandardScaler

preprocessing — модуль подготовки данных.
StandardScaler — класс для стандартизации числовых признаков.
Импорт делает класс доступным; scaler = StandardScaler() создаёт объект.
Объект хранит параметры преобразования каждого входного столбца.

Зачем это нужно нейросети:
Разные признаки могут иметь сильно различающиеся масштабы.
Стандартизация приводит их к сопоставимому масштабу и часто облегчает
работу градиентного оптимизатора. Она не гарантирует хорошую модель
и не делает распределение признака нормальным.

Для каждого столбца отдельно:
  z = (x - mu_train) / sigma_train
  x — исходное значение признака;
  mu_train — среднее этого признака на train;
  sigma_train — стандартное отклонение этого признака на train;
  z — преобразованное значение.

Маленький пример:
  На train среднее признака равно 10, стандартное отклонение равно 2.
  Значение 14 превращается в (14 - 10) / 2 = 2.
  Значение 8 превращается в (8 - 10) / 2 = -1.
  Значение 16 из validation превращается в (16 - 10) / 2 = 3.
  Для validation использованы параметры train, а не новые параметры.

Применение ПОСЛЕ разбиения данных:
scaler = StandardScaler()
X_train = scaler.fit_transform(X_train)
X_validation = scaler.transform(X_validation)
X_test = scaler.transform(X_test)

fit — вычислить и запомнить среднее и масштаб по каждому столбцу train.
transform — применить уже запомненные параметры к данным.
fit_transform — выполнить оба действия для переданного массива.

ВАЖНО:
  fit или fit_transform вызываем только на train.
  Для validation и test используем только transform того же объекта.
  Иначе информация из отложенных выборок попадёт в подготовку модели:
  это утечка данных, нарушающая независимость проверки.
  Метки Y не масштабируем: они остаются 0 и 1.
  Размеры массивов при стандартизации не меняются.

Проверка:
print(X_train.mean(axis=0))
print(X_train.std(axis=0))
axis=0 — считать по строкам отдельно для каждого столбца.
Средние train должны быть близки к 0, стандартные отклонения — к 1.
Постоянный на train столбец после преобразования станет нулевым:
его стандартное отклонение останется 0; StandardScaler не делит на ноль.
На validation и test средние и стандартные отклонения не обязаны
равняться 0 и 1, поскольку параметры определены по train.

Правильный порядок работы:
  загрузка X и Y → разбиение → fit scaler только на train
  → transform всех выборок → обучение на train
  → выбор решения по validation → финальная оценка на test.

ВАЖНЫЙ НЮАНС РИСУНКА
На картинке показана зелёная S-образная линия и точки двух цветов.
В легенде линия названа Boundary, а точки — False samples и True samples.
Без исходного описания нельзя считать эти точки примерами из HIGGS
или утверждать, что True/False обозначают правильные/ошибочные предсказания.

Если вертикальная ось — вероятность, S-образная линия иллюстрирует
изменение вероятности класса 1 при изменении одного входного признака.
Но реальные бинарные метки на таком графике располагаются на 0 и 1,
а не заполняют всю область между ними, как на присланной картинке.

Если обе оси — два исходных признака, обычная логистическая регрессия
без нелинейного преобразования признаков имеет ПРЯМУЮ границу решения,
а не S-образную. Поэтому эта картинка не является точной схемой её
границы решения в пространстве двух исходных признаков.
Сигмоида вероятности и граница решения — разные понятия.

ЧТО ЭТО ЗА МОДЕЛЬ И ЗАЧЕМ ОНА НАМ
Логистическая регрессия — модель классификации, которая оценивает
вероятность класса 1 по входным признакам. Несмотря на слово regression,
в нашем проекте она решает бинарную классификацию: сигнал или фон.
Она будет простым baseline для сравнения с многослойной нейросетью.

ШАГ 1. ЛИНЕЙНАЯ КОМБИНАЦИЯ ПРИЗНАКОВ
z = w1*x1 + w2*x2 + ... + w28*x28 + b
  xi — значение входного признака после подготовки;
  wi — вес признака, подбираемый при обучении;
  b — смещение (intercept), тоже подбираемое при обучении;
  z — суммарный числовой результат, который может быть любым числом.

ШАГ 2. СИГМОИДА — SIGMOID / LOGISTIC FUNCTION
p = 1 / (1 + exp(-z))
  exp(-z) = e в степени -z;
  e ≈ 2.71828 — математическая константа;
  p — оценка P(y=1 | X), вероятности класса 1 при данных признаках.
При конечном z результат находится строго между 0 и 1.

ЧИСЛОВОЙ ПРИМЕР С ДВУМЯ ПРИЗНАКАМИ
Числа учебные, не результаты обучения на HIGGS:
  x1=1, x2=2; w1=0.5, w2=-0.25; b=0.5.
  z = 0.5*1 + (-0.25)*2 + 0.5 = 0.5 - 0.5 + 0.5 = 0.5.
  exp(-0.5) ≈ 0.60653.
  p = 1 / (1 + 0.60653) ≈ 0.62246, то есть примерно 62.2%.
Это оценка модели, а не гарантия правильного ответа.

ШАГ 3. ПЕРЕХОД ОТ ВЕРОЯТНОСТИ К КЛАССУ
Для выбранного порога t=0.5 можно задать правило:
  p > 0.5 → предсказать класс 1;
  p <= 0.5 → предсказать класс 0.
Точное правило при равенстве зависит от реализации; здесь оно указано явно.
В примере 0.62246 > 0.5, поэтому предсказываем класс 1.
Порог — настройка решения, а не дополнительный обучаемый вес модели.

ГРАНИЦА РЕШЕНИЯ — DECISION BOUNDARY
На границе p=0.5. По формуле сигмоиды это соответствует z=0:
  1 / (1 + exp(0)) = 1 / (1 + 1) = 0.5.
Поэтому граница задаётся уравнением:
  w1*x1 + ... + w28*x28 + b = 0.
С одним признаком это порог на числовой оси, с двумя — прямая,
с тремя — плоскость, с 28 — гиперплоскость.
Вероятность нелинейно зависит от z, но граница линейна по входным признакам.

КАК МОДЕЛЬ УЧИТСЯ: LOG LOSS / BINARY CROSS-ENTROPY
Для одного примера:
  L = -[y*ln(p) + (1-y)*ln(1-p)].
  y — истинная метка 0 или 1;
  p — предсказанная вероятность класса 1;
  ln — натуральный логарифм.

Если истинный класс y=1 и p≈0.62246:
  L = -ln(0.62246) ≈ 0.47408.
Если истинный класс y=0 при том же p:
  L = -ln(1-0.62246) = -ln(0.37754) ≈ 0.97408.
Модель получает большую потерю за вероятность, противоречащую ответу.

Для n обучающих примеров усредняем:
  L_mean = (L1 + L2 + ... + Ln) / n.
Обучение подбирает веса и смещение, уменьшая целевую функцию.
В sklearn LogisticRegression по умолчанию также применяется регуляризация:
она ограничивает сложность модели, штрафуя веса. Поэтому фактическая
целевая функция не сводится только к средней BCE, записанной выше.

В НАШЕМ КОДЕ
from sklearn.linear_model import LogisticRegression
baseline = LogisticRegression(max_iter=1000)
baseline.fit(X_train, Y_train.ravel())
predictions = baseline.predict(X_validation)
probabilities = baseline.predict_proba(X_validation)

fit — подобрать параметры на train, а не просто загрузить данные.
max_iter — предел итераций оптимизатора, не число эпох нейросети.
ravel() — превратить метки из формы (N, 1) в (N,).
predict — получить метки классов.
predict_proba — получить вероятности классов; порядок столбцов
соответствует baseline.classes_. Для классов [0, 1] второй столбец
содержит вероятность класса 1.

10. BACKPROPAGATION, ПРОИЗВОДНЫЕ И ОБНОВЛЕНИЕ ВЕСОВ В PYTORCH

ЧТО ТАКОЕ BACKPROPAGATION
Backpropagation — обратное распространение градиента через вычисления
нейросети. Алгоритм вычисляет, как функция потерь зависит от каждого
обучаемого веса и смещения, участвовавших в получении этой потери.
В основе лежит правило цепочки (chain rule) для производных.

Прямой проход (forward pass):
  входные признаки → слои → предсказание → функция потерь L.
Обратный проход (backward pass):
  от L назад через операции → производные по параметрам.

Производная dL/dw показывает локальную чувствительность потери к весу:
  маленькое изменение delta_w даёт примерно delta_L ≈ (dL/dw)*delta_w.
Это приближение для достаточно малых изменений, а не точная формула
изменения ошибки при любом шаге.

Градиент (gradient) — набор частных производных по всем параметрам:
  grad L = [dL/dw1, dL/dw2, ..., dL/db, ...].
Частная производная рассматривает изменение одного параметра
при фиксированных остальных параметрах.

КАК ПРОИЗВОДНЫЕ ВЛИЯЮТ НА ОБУЧЕНИЕ
Для обычного градиентного спуска:
  w_new = w_old - learning_rate * dL/dw.
Если dL/dw положительна, этот шаг уменьшает вес.
Если dL/dw отрицательна, этот шаг увеличивает вес.
Цель — двигаться в сторону уменьшения потери, а не просто увеличивать
все веса или уменьшать их все сразу.
Слишком большой шаг может увеличить потерю или сделать обучение нестабильным.
Оптимизаторы вроде Adam используют дополнительные правила обновления;
формула выше описывает обычный градиентный спуск.

ПОЛНЫЙ ЧИСЛОВОЙ ПРИМЕР
Берём один линейный нейрон без сигмоиды и квадратичную потерю,
чтобы расчёты были видны. Это учебный пример, а не функция потерь
для нашей финальной бинарной классификации HIGGS.

Дано:
  x=2 — вход;
  y=3 — правильный ответ;
  w=0.5 — текущий вес;
  b=0 — текущее смещение;
  learning_rate=0.1 — выбранный размер шага.

Прямой проход:
  prediction = w*x + b = 0.5*2 + 0 = 1.
  error = prediction - y = 1 - 3 = -2.
  L = (prediction - y)^2 / 2 = (-2)^2 / 2 = 2.
Множитель 1/2 выбран для удобства: при дифференцировании он сокращается.

Вычисляем каждую производную:
  dL/dprediction = prediction - y = -2.
  dprediction/dw = x = 2.
  dprediction/db = 1.

Правило цепочки:
  dL/dw = (dL/dprediction)*(dprediction/dw) = (-2)*2 = -4.
  dL/db = (dL/dprediction)*(dprediction/db) = (-2)*1 = -2.

Обновляем ОБА параметра по градиентам, вычисленным до обновления:
  w_new = 0.5 - 0.1*(-4) = 0.9.
  b_new = 0 - 0.1*(-2) = 0.2.

Проверяем результат новым прямым проходом:
  prediction_new = 0.9*2 + 0.2 = 2.
  L_new = (2 - 3)^2 / 2 = 0.5.
В этом примере потеря уменьшилась с 2 до 0.5, предсказание приблизилось к 3.

КАК ЭТО РАБОТАЕТ С НЕСКОЛЬКИМИ СЛОЯМИ
Если вес раннего слоя влияет на a, затем a влияет на z, а z — на L:
  dL/dw = (dL/dz)*(dz/da)*(da/dw).
Если путей влияния несколько, их вклады суммируются.
Так ошибка на выходе позволяет вычислить градиенты даже для ранних слоёв.
Очень маленькие градиенты могут замедлить обучение ранних слоёв
(vanishing gradients), очень большие — сделать обновления нестабильными
(exploding gradients). Эти проблемы нужно диагностировать, а не
приписывать любой плохой результат автоматически именно им.

ЧТО ДЕЛАЕТ PYTORCH
Autograd — механизм автоматического дифференцирования PyTorch.
Он записывает поддерживаемые операции в вычислительный граф, когда
в вычислениях участвуют тензоры, для которых требуется градиент.
Backpropagation — способ пройти этот граф назад и вычислить производные.
Параметры слоёв torch.nn обычно уже имеют requires_grad=True.

В коде обучение разделено на разные действия:
  optimizer.zero_grad() — очистить ранее накопленные градиенты;
  prediction = model(X_batch) — выполнить прямой проход;
  loss = loss_function(prediction, Y_batch) — вычислить потерю;
  loss.backward() — вычислить и накопить градиенты параметров;
  optimizer.step() — обновить параметры по градиентам.

backward() САМ НЕ ОБНОВЛЯЕТ ВЕСА. Их обновляет optimizer.step().
Повторные вызовы backward() на новых графах накапливают градиенты,
поэтому обычно перед очередным шагом их обнуляют.
Замороженные параметры и параметры, не связанные с данной потерей,
не получают градиенты автоматически просто потому, что существуют в модели.

Backpropagation уменьшает обучающую потерю через оптимизацию, но
не гарантирует улучшения на новых данных: возможно переобучение.
Поэтому отдельно наблюдаем train loss и validation loss.

11. ЧТО ТАКОЕ PYTORCH И ЗАЧЕМ ОН НУЖЕН

PyTorch — библиотека для численных вычислений и машинного обучения,
особенно удобная для построения и обучения нейронных сетей.
Устанавливается как пакет torch и импортируется командой:
import torch

PyTorch — инструмент, а не готовая обученная модель и не отдельный
алгоритм обучения. Мы сами выбираем архитектуру, функцию потерь,
оптимизатор, learning rate и порядок экспериментов.

ЧТО ОН ДАЁТ
  1. Тензоры (tensors) — многомерные массивы для хранения данных,
     параметров модели и промежуточных результатов вычислений.
  2. torch.nn — слои, функции активации и функции потерь.
  3. Autograd — автоматическое вычисление производных через граф операций.
  4. torch.optim — оптимизаторы, которые обновляют параметры по градиентам.
  5. Возможность выполнять поддерживаемые вычисления на CPU или GPU.

ТЕНЗОР НА ПРИМЕРЕ НАШИХ ДАННЫХ
  X_train: форма (210, 28) — 210 событий, по 28 признаков в каждом.
  Y_train: форма (210, 1) — по одному ответу на событие.
Оба массива можно представить тензорами. Форма — размеры по осям,
а число осей — размерность тензора. Матрица (210, 28) имеет две оси.
Это не означает, что у события всего два признака: признаков 28.

Пример преобразования:
X_train_tensor = torch.from_numpy(X_train)
Y_train_tensor = torch.from_numpy(Y_train)
Значения сохраняются. from_numpy создаёт CPU-тензор с общей памятью
с исходным NumPy-массивом: изменение одного может изменить другой.
Преобразование само по себе не запускает обучение и не переносит данные на GPU.

КАК СВЯЗАНЫ БИБЛИОТЕКИ НАШЕГО ПРОЕКТА
  csv — чтение исходного CSV.
  NumPy — хранение и обработка числовых массивов, сохранение NPZ.
  scikit-learn — разбиение данных, StandardScaler, логистическая регрессия.
  PyTorch — построение многослойной нейросети и управление её обучением.
NumPy и PyTorch оба умеют численные операции, но PyTorch дополнительно
даёт механизм autograd и инструменты для нейросетей и ускорителей.
В scikit-learn тоже есть нейросети; PyTorch не является обязательным
условием любой нейросети. Здесь он выбран ради контроля над обучением.

12. BCEWithLogitsLoss, backward(), step() И no_grad(): ПО СТРОКАМ

А. СОЗДАНИЕ ФУНКЦИИ ПОТЕРЬ
loss_function = nn.BCEWithLogitsLoss()

Создаём объект, который будет вычислять бинарную перекрёстную энтропию
(Binary Cross-Entropy, BCE), принимая на вход logits — выходы сети
ДО сигмоиды. Эта строка сама ещё не вычисляет потерю и не обучает модель.

Logit z — любое действительное число. Вероятность класса 1 получается так:
  p = sigmoid(z) = 1 / (1 + exp(-z)).
Например, z=0:
  exp(0)=1; p=1/(1+1)=0.5.
Например, z=ln(4)≈1.38629:
  exp(-z)=1/4=0.25; p=1/(1+0.25)=0.8.

Потеря одного примера:
  L_i = -[y_i*ln(p_i) + (1-y_i)*ln(1-p_i)].
  y_i — правильная метка события, 0 или 1;
  p_i — предсказанная вероятность класса 1;
  ln — натуральный логарифм, по основанию e≈2.71828.

Если y=1 и p=0.8:
  L = -[1*ln(0.8) + 0*ln(0.2)] = -ln(0.8) ≈ 0.22314.
Если y=0 и p=0.8:
  L = -[0*ln(0.8) + 1*ln(0.2)] = -ln(0.2) ≈ 1.60944.
Уверенное предсказание неверного класса получает больший штраф.
Логарифм ln(0.8)≈-0.22314 означает, что exp(-0.22314)≈0.8.

При настройках по умолчанию потери усредняются. Для наших N событий
с одним выходом на событие:
  loss = (L_1 + ... + L_N) / N.
Для двух потерь выше:
  (0.22314 + 1.60944) / 2 ≈ 0.91629.

Вызов в коде:
logits = model(X_train_tensor)
loss = loss_function(logits, Y_train_tensor)

Размеры logits и ответов должны совпадать: сейчас (210, 1).
Ответы — числа 0 и 1 в float32, а не номера классов в целочисленном тензоре.
BCEWithLogitsLoss вычисляет эквивалент sigmoid + BCE совместно,
численно устойчивым способом. Не добавляем sigmoid перед этой функцией
и не округляем logits до 0/1 перед вычислением потерь.
Порог используется позже, когда нужны метки классов и метрики.

Б. ВЫЧИСЛЕНИЕ ГРАДИЕНТОВ
loss.backward()

PyTorch проходит вычислительный граф назад и вычисляет производные
потери по связанным с ней обучаемым параметрам. Они накапливаются
в полях .grad этих параметров. Веса эта строка НЕ изменяет.

Для sigmoid + BCE одного события:
  dL_i/dz_i = p_i - y_i.
Если p=0.8, y=1, то производная равна -0.2.
Для среднего по N событиям вклад каждого z_i равен (p_i-y_i)/N.
Далее правило цепочки переносит эти производные на веса всех слоёв.

Градиенты обычно очищают перед очередным шагом:
optimizer.zero_grad()
Иначе новые значения добавятся к ранее накопленным градиентам.

В. ОБНОВЛЕНИЕ ПАРАМЕТРОВ
optimizer.step()

Оптимизатор читает вычисленные градиенты и обновляет параметры,
переданные ему через model.parameters(). Это включает обучаемые
веса и смещения скрытых и выходного слоёв нашей сети.

Для иллюстрации — обычный градиентный спуск:
  w_new = w_old - learning_rate * dL/dw.
  w_old=0.5, learning_rate=0.001, dL/dw=2:
  w_new=0.5-0.001*2=0.498.
У нас используется Adam: он дополнительно учитывает историю градиентов
и их квадратов. Поэтому формула обычного спуска не является точной
формулой обновления Adam.

Если вызвать backward() без step(), веса не обновятся.
Если вызвать step() без свежих градиентов, нового корректного шага
обучения из текущей потери не получится.

Г. ПРОВЕРКА ПОСЛЕ ОБНОВЛЕНИЯ
with torch.no_grad():
    updated_logits = model(X_train_tensor)
    updated_loss = loss_function(updated_logits, Y_train_tensor)

with обозначает блок кода. Внутри no_grad() PyTorch не записывает
новые операции для обратного распространения градиентов.
Вычисления всё равно выполняются, и мы получаем новые значения.
Это уменьшает затраты на хранение графа, который сейчас не нужен.

updated_logits — новый прямой проход с уже обновлёнными весами.
updated_loss — новая потеря на тех же обучающих примерах.
Старый тензор loss не пересчитывается автоматически после step(),
поэтому для сравнения нужен повторный прямой проход.

Пример (условные числа, не результат эксперимента):
  loss до шага = 0.700;
  updated_loss после шага = 0.695;
  уменьшение = 0.700 - 0.695 = 0.005.
Это улучшение потери на train, а не доказательство улучшения на validation.
Один шаг также не обязан уменьшать потерю при любых настройках.

no_grad() не вызывает model.eval(), не обнуляет накопленные градиенты
и не делает параметры навсегда замороженными. Это разные механизмы.
Для проверки сети обычно используют вместе:
  model.eval()
  with torch.no_grad():
      ...
eval() переключает поведение слоёв вроде Dropout и BatchNorm.
В текущей сети только Linear и ReLU, поэтому их поведение при eval()
не меняется. Перед продолжением обучения возвращаем model.train().

ПОЛНАЯ ПОСЛЕДОВАТЕЛЬНОСТЬ ОДНОГО ШАГА
  zero_grad → forward → loss → backward → step.
Затем отдельный forward без градиентов для проверки результата.
loss.item() превращает одноэлементный тензор потери в Python-число,
удобное для вывода и записи истории.
